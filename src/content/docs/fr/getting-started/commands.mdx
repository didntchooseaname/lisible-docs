Toutes les commandes se lancent depuis la racine. Les scripts de proxy transmettent l’action à la variante active.

## Cycle quotidien

| Commande | Rôle |
| --- | --- |
| `bun run init` | configuration guidée et installation |
| `bun run dev` | serveur Astro de la variante active |
| `bun run build` | génération statique dans `dist/` |
| `bun run preview` | aperçu local du dernier build |
| `bun run variant` | affiche la variante active |

## Comparer les variantes

Le [preview interactif en direct](/docs/features/live-preview/) est le moyen le plus rapide de comparer une révision publique synchronisée et de partager ses réglages. Pour comparer la source actuellement checkout sur votre machine, lancez :

```bash
bun run preview:all
```

La commande prépare les six variantes puis les sert sur les ports `4321` à `4326`. Elle est conçue comme un workflow complet, pas comme un simple wrapper autour d’anciens builds.

## Créer un article

```bash
bun run new-post mon-premier-article
bun run new-post my-first-post --locale en
bun run new-post paired-post --translate
bun run new-post plain-markdown --markdown
```

Le scaffolder refuse d’écraser un fichier existant et crée par défaut un brouillon `.mdx` au frontmatter valide. `--markdown` est l’option explicite pour obtenir un fichier `.md`.

Les champs générés sont documentés dans [Modèle de contenu](/docs/authoring/content/) et dans la [Référence complète](/docs/reference/configuration/).

## Contrôles inter-variantes

```bash
bun run check-links
bun run check-assets
bun run typecheck
bun run check:all
```

`check-links` et `check-assets` portent sur la variante active. `typecheck` exécute `astro check` sur chaque variante. `check:all` valide d’abord les assets Open Graph, le style éditorial et la conformité inter-variantes, puis typecheck, build et valide les liens, les budgets d’assets et les images Open Graph des sept. Passez un nom de variante pour restreindre l’exécution :

```bash
bun run check-variants organique
```

## Tests, lint et dérive

| Commande | Rôle |
| --- | --- |
| `bun run test` | tests unitaires des helpers partagés |
| `bun run test:e2e` | suite Playwright de bout en bout sur les variantes construites |
| `bun run lint` | vérification lint et format Biome |
| `bun run format` | application du format Biome |
| `bun run check-style` | règles éditoriales : aucun tiret long, aucun emoji dans la documentation |
| `bun run check-drift` | compare le HTML construit à une base de référence (`--save` la capture) |

`test:e2e` attend des variantes construites et Chromium installé (`bun x playwright install chromium`). [Qualité et accessibilité](/docs/operations/quality/) explique quand chaque contrôle prend son sens.

:::tip[CI]
Le dépôt fournit un pipeline GitHub Actions qui exécute Biome, les tests unitaires et les règles de style, puis `check-variants` sur une matrice filtrée par chemins, la suite Playwright et les budgets Lighthouse. En local, `bun run check:all` reste l’équivalent bloquant le plus proche avant de pousser.
:::

## Gestion des dépendances

Le dépôt est un workspace Bun : un seul `bun install` à la racine couvre l’outillage, le cœur partagé, chaque variante et les paquets npm. Le flux normal depuis la racine installe automatiquement ce qui manque.
