Lisible utilise Bun pour ses scripts et ses installations reproductibles. Une version récente de Git et Bun suffit pour démarrer. Une fois Bun présent, les scripts `run` fonctionnent aussi via npm ou pnpm si vous les préférez.

:::tip[Tester avant d’installer]
Le [preview interactif en direct](/docs/features/live-preview/) exécute les six variantes depuis un commit source exact et synchronisé, puis permet de partager les réglages choisis.
:::

## Prérequis

- Git ;
- Bun ;
- un navigateur moderne ;
- facultatif : Node.js si votre environnement l’impose pour certains outils externes.

```bash title="Installer Bun sur macOS ou Linux"
curl -fsSL https://bun.sh/install | bash
```

## Générer un blog (recommandé)

Le paquet npm `lisible` crée un blog prêt à éditer en une commande :

```bash
bun create lisible mon-blog
```

`npm create lisible@latest mon-blog` fonctionne de la même façon. Le générateur télécharge le modèle, le détache de l’historique du framework, initialise un dépôt Git neuf et lance l’assistant guidé. Les options placées après le dossier sont transmises à l’assistant pour une génération non interactive :

```bash
bun create lisible mon-blog --yes --variant organique --title "Mon blog"
```

## Autres façons d’obtenir le code

- **Modèle GitHub.** [Use this template](https://github.com/didntchooseaname/lisible/generate) crée votre propre dépôt avec un historique propre, à cloner ensuite.
- **degit.** `bunx degit didntchooseaname/lisible mon-blog` copie les fichiers sans aucun historique Git.
- **Contribuer à Lisible.** Clonez le dépôt et renommez le remote en `upstream` pour que votre propre dépôt puisse devenir `origin` plus tard.

Après chacune de ces options, lancez l’assistant vous-même :

```bash
bun run init
```

## L’assistant de configuration

L’assistant demande la variante, le titre et l’URL publique, puis s’arrête là (mode rapide) ou permet d’affiner l’auteur, la couleur d’accent et le dépôt (mode détaillé). Tout est écrit dans `lisible.config.json` et les dépendances de la variante choisie sont installées automatiquement. Les configurations non interactives passent les mêmes options que le générateur : `bun run init --yes --variant organique --title "Mon blog"`.

La page [Configuration initiale](/docs/getting-started/configuration/) détaille chaque valeur écrite par l’assistant, et [Commandes](/docs/getting-started/commands/) couvre le cycle quotidien.

:::note[Ordre flexible]
`bun run preview:all` fonctionne aussi sur un clone frais, avant ou après `init`. La commande installe et reconstruit les six variantes avant de les servir.
:::

## Démarrer le serveur

```bash
bun run dev
```

Le script racine lit la variante active et lance son serveur Astro. Les modifications du contenu partagé sont reflétées immédiatement.

## Vérifier l’installation

- la page française répond à `/` ;
- la version anglaise répond à `/en/` ;
- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd> + <kbd>K</kbd> ouvre la palette ;
- le thème et l’accent persistent après navigation ;
- aucun dossier `node_modules` ou `dist` n’est ajouté à Git.

:::tip[Recherche en développement]
Pagefind indexe les pages pendant le build. En mode `dev`, la palette reste fonctionnelle et explique que les résultats plein texte seront disponibles après `bun run build && bun run preview`.
:::
